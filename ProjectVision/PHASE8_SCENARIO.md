# Phase 8 — 场景推演与设计决策

> 目标：从人工调度到有机 Flow，用户只需 `/goal`，平台自动协作完成。

---

## 核心流程

```text
用户: /goal <需求>
  → PM 逐条引导讨论（或 "全权处理" 跳过）
  → PM 拆解任务 + 写入 Wiki/记忆 + 落地 .md 文档
  → 按 best_for 分派 Agent
  → 并行执行 + 心跳监控（7 维度）
  → Agent 卡住 → 卡住摘要 → 返人工
  → 用户可半路介入
  → PM 汇总验收
```

---

## 设计决策

### 1. PM 讨论引导

PM 逐条提问（不一次性全抛），用户可逐条回复或直接"全权处理"跳过。选择题同时提供面板点选。

### 2. 文档双输出

| 输出 | 去向 | 用途 |
| --- | --- | --- |
| 详细内容（技术方案、决策理由） | 记忆/Wiki | Agent 沉淀查询 |
| 概要（API 文档、使用说明） | `.md` 文件 | 人类阅读、随版本管理 |

### 3. 测试隔离

编码 Agent 与测试 Agent 分离，不允许同一 Agent 又写又测。测试输出必须包含计划、用例、结果。

### 4. 心跳 7 维度

存活 / 进展 / Token / 文件变动 / 重复检测 / 错误率 / 耗时。30s 轮询，Token 暴涨 + 无进展 = 卡住了，生成摘要返人工。

### 5. 风险围栏

| 等级 | 默认行为 |
| --- | --- |
| 读 | 无围栏 |
| 低风险写（注释、日志） | 无围栏 |
| 中风险写（改函数） | 记录不打断 |
| 高风险写（删文件、改 schema） | 弹确认 |
| 极度危险（删库、rm -rf） | 拒绝 |

安全模式：YOLO / 标准 / 保守，用户可切换。

### 6. 多层 /goal

一个会话一个 PM，新 /goal 默认意图不明确，PM 引导用户决定：追加 / 变更 / 终止。任务面板按 /goal 分组展示。
