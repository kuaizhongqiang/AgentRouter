# AgentRouter — 核心概念

> **多开源 CLI 编程助手调度器**

---

## 一句话定义

一个桌面平台，**不写代码，只调度**——把多个开源 CLI 编程助手整合到一起，像管一个团队一样管它们。

---

## 概念模型

### 🎯 调度器（Scheduler）— 平台的灵魂

调度器是 AgentRouter 的核心。它不做技术决策，只做三件事：

| 职责 | 含义 |
|---|---|
| **谁来做** | 选哪个 Agent 处理这个任务 |
| **什么时候做** | 按依赖关系决定执行顺序 |
| **怎么做** | 按执行模式（YOLO/审批/逐步/预览）控制节奏 |

调度器不读代码、不写文件、不改任务内容——这些是 Agent 的事。

### 🔌 Agent 适配器（Adapter）— CLI 的翻译官

每个 CLI 编程助手通过一个适配器挂到平台上：

```
AgentRouter
  ├── [CodeWhale 适配器] → spawn ar-codewhale
  ├── [Reasonix 适配器] → spawn ar-reasonix
  └── [未来其余 CLI 适配器] → ...
```

适配器只做翻译：
- 平台指令 → CLI 命令行参数
- CLI stdout 事件流 → 平台统一事件格式

### 📦 任务（Task）— 最小工作单元

```
{
  id: "t1",
  title: "数据库：添加 roles 表",
  assignee: "codewhale",        // 谁做
  path: "./src/models/",        // 在哪做
  depends_on: [],               // 依赖谁
  parallel_group: 1             // 并行组
}
```

任务之间有依赖关系（DAG），调度器按并行组调度。

### 💬 会话（Session）— 上下文容器

一次需求的完整生命周期：从用户输入 → PM 拆解 → 多 Agent 执行 → 结果汇聚。

### 📁 项目（Project）— 工作边界

一个本地代码仓库 = 一个项目。项目是持久化的最小单位。

## 工作流

```
用户输入需求
     │
     ▼
┌─────────────┐
│  调度器路由  │ ← 用户选 PM Agent（默认 Reasonix）
└──────┬──────┘
       │ spawn
       ▼
┌─────────────┐
│  PM Agent   │ → 分析需求 → 产出结构化任务列表
│ (Reasonix)  │    { tasks: [...], parallel_groups: [...] }
└──────┬──────┘
       │ 返回任务列表
       ▼
┌─────────────┐
│  调度器      │ → 按 parallel_groups 调度
│             │    第1组: t1 → CodeWhale
│             │    第2组: t2 + t3 → CodeWhale（并行）
│             │    第3组: t4 → Reasonix
└──────┬──────┘
       │ spawn
       ▼
┌─────────────┐
│  各 Agent    │ → 各自执行 → 输出事件流
│  并行工作    │    task:start → progress → completion
└──────┬──────┘
       │ 汇聚
       ▼
┌─────────────┐
│  UI 展示     │ → 用户看到完整执行链路
└─────────────┘
```

## 四种执行模式

| 模式 | 行为 | 适合场景 |
|---|---|---|
| **YOLO** 🚀 | 全自动，PM拆完直接执行 | 老手、简单任务 |
| **审批** ✅ | 展示任务列表→用户确认→执行 | 重要项目、团队协作 |
| **逐步** 👣 | 每组执行前询问用户 | 想跟进度但不审全部 |
| **预览** 👀 | 只看计划不执行 | 需求分析阶段 |

---

## 边界定义（不做什么）

| 不做 | 原因 |
|---|---|
| 不做 IDE | VS Code / WebStorm 已经做得很好了 |
| 不做新 CLI | 社区已有优秀的开源 CLI（CodeWhale、Reasonix、Continue 等） |
| 不做能力增强 | Agent 自身能力由上游项目决定 |
| 不干涉 CLI 内部逻辑 | 只监 stdout，不改行为 |
| 不自己调用 MCP/工具 | 那是 CLI 的事，不是平台的事 |

---

## 愿景

### 短期（Phase 1）
跑通 **"PM 拆任务 → 多 Agent 并行执行"** 的完整闭环。用户能看到一个 AI 团队在工作。

### 中期（Phase 2-3）
- Agent 生态：可插拔，社区贡献适配器
- 记忆系统：跨会话、跨项目的长期记忆
- MCP 集成：CLI 可通过平台调用工具

### 长期
成为 AI 编程时代的 **"操作系统层"**——开发者不需要关心底层用哪个 CLI、怎么调度，AgentRouter 自动把任务分配给最合适的工具。

就像 Android 不关心 App 用什么语言写，AgentRouter 不关心 Agent 用什么模型跑。
